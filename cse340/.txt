app.post("/account/login", async (req, res) => {
    const { email, password } = req.body;

    const result = await db.query(
        "SELECT * FROM account WHERE account_email = $1",
        [email]
    );

    const user = result.rows[0];

    if (!user) {
        req.flash("notice", "Invalid email or password.");
        return res.redirect("/account/login");
    }

    const passwordMatch = await bcrypt.compare(
        password,
        user.account_password
    );

    if (!passwordMatch) {
        req.flash("notice", "Invalid email or password.");
        return res.redirect("/account/login");
    }

    req.session.user = {
        account_id: user.account_id,
        account_firstname: user.account_firstname,
        account_type: user.account_type
    };

    res.redirect("/account/");
});

This code looks up the account using the email address and then compares the password entered by the user with the hashed password stored in the database. If the password is correct, the user's information is stored in the session.

Hellen: Because the database contains a hashed password, not the original password. bcrypt.compare() checks whether the password the user entered matches the stored hash without needing to turn the stored hash back into the original password.

Hellen: I store information such as the account ID, first name, and account type. The account type is useful because the application can use it to determine what the user is allowed to access.

Topic 3: Protected Access Middleware

AI Coach: Let's discuss protected access middleware. Could you paste a snippet showing how your requireLogin and requireRole middleware protects routes?

Hellen:

function requireLogin(req, res, next) {
    if (!req.session.user) {
        req.flash("notice", "Please log in to access this page.");
        return res.redirect("/account/login");
    }

    next();
}

function requireRole(role) {
    return (req, res, next) => {
        if (!req.session.user) {
            req.flash("notice", "Please log in first.");
            return res.redirect("/account/login");
        }

        if (req.session.user.account_type !== role) {
            req.flash("notice", "You do not have permission to access this page.");
            return res.redirect("/account/");
        }

        next();
    };
}

I use requireLogin when a page should only be available to logged-in users. I use requireRole when a page should only be available to a specific type of user.

Topic 3: Protected Access Middleware

AI Coach: What is the main difference between requireLogin and requireRole in your application?

Hellen: requireLogin checks whether a user is logged in. It does not necessarily care what type of user they are. requireRole goes further by checking the user's role or account type to make sure they have permission to access a particular resource.

AI Coach: Why does the middleware call next() when the user passes the required checks?

Hellen: next() tells Express that the middleware has finished and that the request can continue to the next middleware or the route handler. If the user does not pass the checks, the middleware redirects them instead of calling next().

AI Coach: How might you use requireRole() on a route that should only be available to an administrator?

Hellen: I could use it as middleware before the route handler, for example:

router.get("/admin", requireRole("Admin"), accountController.admin);

This means the user must be logged in and have the Admin account type before the route can continue.

AI Coach: What security problem could occur if you only hid an administrator page from the navigation but did not protect the route with middleware?

Hellen: A user could still manually type the URL into the browser and possibly access the page. Hiding the link only changes what the user sees. Middleware actually protects the server-side route.
